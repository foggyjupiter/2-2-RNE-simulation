# 실측 추가 녹음 절차서

시뮬레이션으로 학습한 모델을 **실제로** 검증하고 시뮬레이터를 보정하는 데 필요한 녹음입니다.
우선순위 순서입니다. 1~2번만 해도 "물질을 모르는 개수 추정"과 "다중 rpm 모델"을 실측으로 검증할 수 있습니다.

## 공통 조건 (1차 연구와 똑같이)

- 상자: 5×5×7 cm 아크릴 상자, 가진 장치에 고정
- 마이크: Galaxy S25 + Motiv Audio, **48 kHz**, 상자에서 약 **2.7 m**, 위치·방향 고정 (테이프로 바닥 표시)
- **게인을 고정**하세요. 자동 게인·잡음 제거·리미터는 끄세요(앱 설정에 있으면). 1차 녹음과 같은 설정이 가장 좋습니다.
- 한 번에 **7초 이상** 녹음하고, 가진이 안정된 뒤 시작합니다 (모델은 가운데 5초만 씀).
- 방 조건(문, 커튼, 가구 위치)과 시간대를 가능한 한 같게 유지합니다.
- 파일 이름: `{입자종류}_N{개수}_rpm{속도}_{반복번호}.wav` (예: `bb012_N050_rpm372_03.wav`)
- 각 세션마다 `recordings.csv`에 한 줄씩 기록: 파일, 입자종류, 개수, rpm(또는 전원 전압), 날짜, 비고

rpm은 전원 전압으로 조절하므로, **전압과 rpm의 대응**을 한 번 재 두면 좋습니다 (휴대폰 슬로모션 영상이나 소리의 주기로 확인. 소리로 재는 방법은 `gransim`의 분석 코드가 알아서 추정합니다: 372 rpm = 6.2 Hz).
1차 연구 녹음을 분석해 보니 **같은 설정에서도 속도가 클립마다 6.04~6.64 Hz로 달랐고**, N = 95·100은 약 6.5 Hz였습니다. 입자가 많을수록 모터 부하가 달라지거나 배터리·전원 상태가 변했을 수 있습니다. 그래서:
- 녹음할 때마다 `recordings.csv`에 전압을 적고, 가능하면 그때의 rpm도 적어 주세요 (소리로도 추정 가능하지만 확인용).
- 같은 개수 안에서 순서를 섞어 녹음하면(예: 20 → 80 → 50 → 20 …) 속도 변화가 개수와 엮이지 않습니다.

## 1. 다른 입자로 녹음 (물질을 모르는 추정의 진짜 시험) ★★★

모델은 물성을 모른 채 개수를 맞혀야 합니다. 1차 연구와 **다른 물질**로 녹음해야 이것을 실측으로 검증할 수 있습니다.

| 입자 | 예 | 준비 |
|---|---|---|
| 무게가 다른 6 mm BB | 0.20 g, 0.25 g, 0.30 g, 0.40 g | 시판 |
| 8 mm BB | 0.34 g 전후 | 시판 |
| 유리·플라스틱 구슬 | 4~8 mm | 지름 고른 것 |

- 입자마다 **지름(버니어캘리퍼스, 10개 평균)과 무게(50개 무게 ÷ 50)**를 재서 기록합니다. 반발계수는 모르는 채로 둡니다 (모델이 추정).
- 개수: 0, 10, 20, 35, 50, 75, 100 (가능하면 더). 개수당 **5회**.
- rpm: 372 (1차 연구와 같음). 2번을 할 수 있으면 그 rpm들도.
- 입자를 바꿀 때 상자를 깨끗이 털고, 같은 개수로 다시 담을 때는 저울로 확인하면 빠릅니다.

## 2. 같은 상자를 여러 rpm으로 (다중 조건 모델 검증) ★★★

시뮬레이터의 다중 조건 데이터셋은 **300 / 372 / 450 / 550 / 650 rpm**에서 만듭니다. 같은 rpm(±5 %)에서 녹음해 주세요.

- 개수: 최소 20, 50, 80 (가능하면 0~100 전부 10개 단위)
- 각 개수에서 5개 rpm을 **연달아** 녹음 (입자를 꺼내지 않고 전압만 바꿈). 회당 7초 이상.
- 개수당 3회 반복
- BB(0.12 g)부터 하고, 1번의 다른 입자도 가능하면 같은 방식으로

## 3. 빈 상자를 각 rpm에서 (모터 잡음 라이브러리) ★★

- 입자 없이 300 / 372 / 450 / 550 / 650 rpm에서 각각 **30초** 1회
- 지금은 372 rpm 잡음만 있어서 다른 rpm은 재생 속도를 바꿔 근사합니다. 실측으로 바꾸면 근사가 사라집니다.

## 4. 단일 입자 낙하 (반발계수·충돌음 하나의 모양) ★★

시뮬레이션의 충돌음이 실제보다 "또렷하고 많다"는 차이를 직접 진단하는 데 씁니다.

- 상자를 가진 장치에 단 채로(정지), 위 뚜껑을 열고 BB 하나를 **10 cm 높이에서** 바닥 가운데로 떨어뜨립니다. 10회.
- 같은 방법으로 **바닥 모서리 근처**(벽에서 5 mm)에 10회 → 충돌 위치에 따라 소리가 얼마나 다른지 (시뮬레이터에 넣은 "위치에 따른 방사 효율" 가설의 검증)
- 가능하면 휴대폰 슬로모션(240 fps)으로 옆에서 촬영 → 튀어 오른 높이로 반발계수 계산 (e = √(h₂/h₁))
- 다른 입자(1번)도 같은 방법으로 하면 입자별 실제 반발계수를 얻습니다 → 모델이 추정한 반발계수와 비교 가능
- 낙하 녹음은 **그 입자의 실제 충돌음 라이브러리**도 됩니다: `gransim build-clicks "<폴더>/glass6mm_*.wav" --out assets/impacts/clicks_glass6mm.npz` 후 `acoustics.impact_source: recorded`, `acoustics.click_library: <파일>`로 합성하면 시뮬레이션 충돌 시점에 실제 녹음된 충돌음이 들어갑니다 (BB용은 1차 연구 N = 5·10 녹음의 고립된 충돌 600개로 이미 만들어 둠: `assets/impacts/clicks_bb.npz`).
- **BB 위로 떨어뜨리기**: 바닥에 BB 하나를 양면테이프로 고정하고 그 위에 다른 BB를 10 cm에서 떨어뜨려 10회 (BB끼리의 반발계수). 시뮬레이션 비교는 "BB끼리는 거의 탄성(약 0.95), BB-아크릴 벽은 약 0.7"을 가리키는데, 이 두 측정으로 직접 확인할 수 있습니다.
- **슬로모션으로 상자 전체**: 가진 중 N = 20과 N = 100에서 옆에서 240 fps로 5초씩. 입자들이 한꺼번에 뜨고 떨어지는지(동기화), 상자가 수직으로만 움직이는지(흔들림) 확인용입니다.

## 5. 개수별 임펄스 응답 (용기 응답의 개수 의존) ★

시뮬레이터의 용기 응답은 지금 개수와 무관합니다. 입자가 많으면 실제로는 울림이 더 빨리 죽을 수 있습니다.

- 가진 장치를 끈 상태에서 입자를 넣고(정지), 상자 바닥 옆면을 **연필 끝(또는 작은 쇠구슬)으로 가볍게 톡** 칩니다. 같은 위치, 같은 세기로 10회.
- 개수: 0, 25, 50, 100, 200, 300
- 바닥 / 옆면 / 뚜껑을 각각 따로 치면 더 좋습니다 (벽별 응답).

## 6. 반복성 (허용 오차 기준) ★

- 1~2번 녹음 중 몇 조건을 **다른 날** 한 번 더 녹음 → 날마다 얼마나 달라지는지 = 모델 평가의 허용 오차 기준

## 녹음 후

파일과 `recordings.csv`를 한 폴더에 모아 주시면 됩니다. 이후 처리는 자동입니다.

- **먼저 점검**: `gransim check-recordings <폴더>` — 파일마다 형식(wav·48 kHz·길이), 음량·클리핑, 소리로 잰 가진 속도와 적어 둔 속도의 차이, 같은 조건 반복 중 음량이 튀는 파일, `recordings.csv`와 파일 목록의 불일치를 알려 줍니다 (`<폴더>/check_report.csv`). 1차 연구 녹음에 돌려 보면 N = 95·100 클립 대부분이 설정보다 5~7 % 빠르게 잡힙니다. 휴대폰이 m4a로 저장했다면 48 kHz wav로 바꿔 주세요.

- 잡음 라이브러리·응답 모델 갱신: `gransim build-assets <폴더> --rpm <rpm>`
- 실측 대비 시뮬레이션 비교: `gransim`의 sim2real 비교
- 모델 평가: `rneml evaluate <모델> --real-dir <폴더>`, 새 녹음 추정: `rneml predict <파일들> --run <모델>`
